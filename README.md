# 报销预审数字员工（Expense Review Agent）

面向企业财务共享场景的**岗位级数字员工**演示系统：上传报销单与发票票据，数字员工自动完成
票据识别、字段抽取、政策校验、异常判定与预审意见生成，每条结论都绑定票据证据与政策条款，
高风险单据强制进入人工审批，全程留痕。

> 所有发票、员工与数据均为虚构演示数据。

---

## 1. 核心能力

| 模块 | 能力 |
|---|---|
| 数字员工工作台 | 今日处理量、自动通过率、核准金额、规则命中分布、处理趋势 |
| 报销单管理 | 列表、状态筛选、搜索、分页；每条 AI 结论可展开看证据与政策原文 |
| 票据识别 | 增值税发票 / 航空行程单 / 铁路客票；文本层直读，扫描件自动 OCR |
| 规则引擎 | 18 条确定性规则：金额一致、日期窗口、城市限额、重复报销、抬头校验、包干标准、招待费审批等 |
| 预审决策 | 通过 / 复核 / 退回 三级结论，附置信度、建议可报金额与风险等级 |
| 人机协同 | 审批人可修改金额、通过或驳回；AI 结论与人工决定同时留痕 |
| 政策库 | 6 部政策、条款级检索；规则结论自动引用具体条款 |
| 审计与权限 | 登录 / 查阅 / 审批 / 驳回 / 修正全程留痕；员工只能看本人单据 |

## 2. 快速启动

### Docker（推荐）

```bash
cd expense-agent
docker compose up -d --build
```

打开 http://localhost:8013 ，使用 approver / Approve@123 登录。

首次启动自动导入：5 个账号、6 部政策、8 张报销单（12 份票据，其中 1 份纯扫描件走 OCR）。

```bash
docker compose logs -f     # 查看日志
docker compose down        # 停止
```

### 本地 Python

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -r requirements.txt
python scripts\init_db.py     # 初始化数据
uvicorn app.main:app --port 8012
```

打开 http://localhost:8012 。

### 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| EXPENSE_DATA | ./data | 数据库、上传票据、OCR 页面图 |
| EXPENSE_SEED | ./seed | 演示票据与数据清单 |
| SEED_ON_START | 1 | 首次启动是否导入演示数据 |
| OCR_DPI | 170 | 扫描件渲染分辨率 |
| SESSION_DAYS | 7 | 会话有效期 |

## 3. 技术架构

```
浏览器（原生 HTML/CSS/JS，零构建）
        | REST + HttpOnly Cookie
FastAPI |- 认证与 RBAC（PBKDF2）
        |- 报销单 CRUD / 上传 / 审批 / 审计
        '- 任务队列与执行轨迹
执行引擎（后台线程）
  票据解析（文本层 / RapidOCR）-> 字段抽取 -> 明细生成
  -> 18 条确定性规则 -> 预审决策 -> 结构化落库
知识层：政策库 + 条款级检索（jieba + 评分）
存储：SQLite（WAL）+ 本地文件
```

### 关键设计取舍

| 决策 | 原因 | 代价 |
|---|---|---|
| 确定性规则优先，不用 LLM 判金额 | 金额/日期/重复必须是精确判断，规则可测试、可解释 | 语义类规则（如招待合理性）暂未实现 |
| 每条结论绑定政策条款 | 能讲清依据是什么，也支持员工申诉 | 需要维护政策库与规则映射 |
| 高风险强制人工审批 | 生产环境可落地，避免全自动决策的合规风险 | 需要审批人角色与交互 |
| AI 结论与人工决定分开存储 | 支持 AI 建议 vs 人工修正对比，形成反馈闭环 | 表结构多一张 approvals |
| SQLite + 本地文件 | 单机演示零依赖 | 并发写入有限，生产需迁移 PostgreSQL |

## 4. 规则引擎明细

| 规则 | 判定 | 级别 |
|---|---|---|
| R001 发票抬头 | 购买方必须是公司全称 | 阻断 |
| R002 发票重复 | 发票号码不得在其他报销单中使用 | 阻断 |
| R003 住宿标准 | 每晚单价不超过城市限额（上海 700 / 厦门 450 / 其他 380） | 提示 |
| R004 住宿重复 | 同城同日多张住宿发票 | 阻断 |
| R005 行程完整 | 必须有出差起止日期 | 阻断 |
| R006 行程倒置 | 结束日期不得早于开始日期 | 阻断 |
| R007 票据日期 | 票据日期必须落在出差期间内 | 阻断 |
| R008 开票日期 | 开票日期不得晚于提交日期 | 阻断 |
| R009 报销时限 | 开票后超过 30 天提交需说明 | 提示 |
| R010 金额一致 | 票据合计 = 明细合计 | 阻断 |
| R011 申报金额 | 申报金额 = 明细合计 | 阻断 |
| R012 餐饮标准 | 餐饮不超过 100 元/天包干 | 提示 |
| R013 市内交通 | 不超过 80 元/天包干 | 提示 |
| R014 招待费 | 超过 2000 元需事前审批 | 提示 |
| R015 费用混报 | 招待费与差旅费分开填报 | 提示 |
| R016 行程一致 | 票据目的地与出差申请一致 | 提示 |
| R017 票据完整 | 差旅报销需有交通或住宿票据 | 阻断 |
| R018 票据缺失 | 报销单必须有票据 | 阻断 |

通过项也会记录（状态 pass），让审批人看到哪些规则查过、没有问题。

## 12. 接入大模型（可选，7B 私有化 / 任意 OpenAI 兼容端点）

系统默认**规则模式**：所有判定由 18 条确定性规则完成，审核意见用模板生成。
配置 LLM 后自动升级为**规则决策 + 模型表达**：规则仍然负责通过/复核/退回，
模型只负责生成自然语言审核意见与"事由-费用匹配"语义判断。

### 12.1 三种接法

| 方式 | 配置 | 适用 |
|---|---|---|
| vLLM 私有化 | LLM_BASE_URL=http://<host>:8000/v1 | 生产，数据不出内网 |
| Ollama | LLM_BASE_URL=http://<host>:11434/v1 | 开发机，零成本 |
| 云 API（百炼/DeepSeek） | 对应官方 OpenAI 兼容地址 | 快速验证 |

### 12.2 vLLM 部署 Qwen2.5-7B-Instruct

```bash
pip install vllm
vllm serve Qwen/Qwen2.5-7B-Instruct-AWQ --max-model-len 8192 --gpu-memory-utilization 0.85 --quantization awq --port 8000
```

- AWQ 4-bit 显存约 5.5GB，加 KV Cache 峰值约 16GB，单卡 24G 可跑
- 输入 2K / 输出 300 tokens 时约 8-12 并发，首 token 约 300ms

### 12.3 本机验证（无需 GPU）

项目内置 scripts/mock_llm.py，模拟 OpenAI 兼容接口：

```bash
# 终端 1
python -m uvicorn scripts.mock_llm:app --port 8020

# 终端 2
$env:LLM_BASE_URL="http://127.0.0.1:8020/v1"
$env:LLM_API_KEY="mock-key"
$env:LLM_MODEL="Qwen2.5-7B-Instruct"
uvicorn app.main:app --port 8014
```

页面顶栏会显示"Qwen2.5-7B-Instruct 已接入"，意见来源标记为"大模型生成"。

### 12.4 降级行为

| 场景 | 行为 |
|---|---|
| 未配置 LLM | 模板意见；语义规则 R020 不出现；trace 无"LLM 审核意见" |
| 调用超时/失败 | 自动降级为模板，trace 记录降级原因；单据照常流转 |
| 返回格式错误 | 语义规则跳过；意见回退模板 |

降级不影响决策准确性：通过/复核/退回始终由确定性规则给出。
